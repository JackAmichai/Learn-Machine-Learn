## 2024-05-24 - Client-Side API Key Exposure via Vite Environment Variables
**Vulnerability:** The application was configured to read a Hugging Face API token (`VITE_HF_TOKEN`) from the environment (`import.meta.env`) and inject it into the client-side JavaScript bundle.
**Learning:** In Vite (and similar bundlers like Webpack or CRA), variables prefixed with `VITE_` (or `REACT_APP_`) are statically replaced at build time. This means if a developer uses their own token during the build, it is permanently exposed in plaintext to anyone inspecting the client-side source code, leading to potential token theft and abuse.
**Prevention:** For client-side applications that interact with third-party APIs requiring authentication, do not use environment variables to bundle API keys. Instead, implement a Bring-Your-Own-Key (BYOK) architecture where the user provides their own token at runtime (e.g., via a UI setting) and securely store it in `localStorage` or `sessionStorage`.
